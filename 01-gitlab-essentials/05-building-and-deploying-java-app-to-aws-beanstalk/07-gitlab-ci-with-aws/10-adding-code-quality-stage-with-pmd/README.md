## Introduction

Ensuring code quality is crucial for maintaining a robust and error-free application. PMD is a static code analysis tool that helps detect bad practices, bugs, and security vulnerabilities. This guide will help you add a PMD code quality stage to your CI/CD pipeline, ensuring that your codebase remains clean and maintainable.

## Setting Up the Code Quality Stage

### Creating the Stage

To introduce the code quality stage, we'll add it to the existing pipeline configuration. We will place it within the `test` stage for simplicity, allowing it to run alongside other tests.

### Choosing the Docker Image

Since we're using Gradle, we need a Docker image that comes with JDK. We'll use the `openjdk:12-alpine` image, which is lightweight and includes the necessary JDK.

### Accessing the PMD Reports Path

Accessing the `./build/reports/pmd` path is essential for reviewing PMD (Programming Mistake Detector) reports in a Java project. PMD identifies common programming flaws such as unused variables, empty catch blocks, and unnecessary object creation. Here’s why accessing this path is important:

- **Reviewing Code Quality Reports**: This directory contains PMD reports generated after a build. Accessing it allows developers to review and address any code quality issues identified by PMD.
- **Continuous Integration (CI) Processes**: In CI pipelines, automated tools may need access to PMD reports to enforce code quality gates, ensuring that code quality issues are addressed promptly.

To get the path of a specific file or directory in your Java project within IntelliJ IDEA:

1. **Open Your Project**: Start by opening your Java project in IntelliJ IDEA.
2. **Navigate to the File or Directory**: Use the Project view on the left side to navigate to the file or directory.
3. **Select the File or Directory**: Click on the file or directory to select it.
4. **Copy Path**: Right-click on the file or directory. In the context menu, choose "Copy Path From Repository Root" or "Copy Absolute Path".
   - **Copy Path From Repository Root**: Copies a relative path from the repository root.
   - **Copy Absolute Path**: Copies the full path on your filesystem.
5. **Choose the Appropriate Option**: Click on either "Copy Path From Repository Root" or "Copy Absolute Path" depending on your need.

### Writing the Script

We'll use the same PMD command that you run locally. Here's the complete configuration for the code quality stage in your `.gitlab-ci.yml` file:

```yaml
code quality:
  stage: test
  image: openjdk:12-alpine
  script:
    - ./gradlew pmdMain pmdTest
  artifacts:
    when: always
    paths:
      - ./build/reports/pmd
```

### Explanation

1. **Stage**: Defines the pipeline stage.
2. **Image**: Specifies the Docker image to use.
3. **Script**: Runs the PMD analysis.
4. **Artifacts**: Ensures that the report is always available, even if the job fails.

## Managing Artifacts

Artifacts are files generated by your pipeline that you want to keep. In our case, the PMD report is the artifact we want to preserve. By setting `when: always`, we ensure that the report is retained regardless of the job's success or failure.

To view the report:
1. Navigate to the GitLab job page.
2. Find the artifact section and download the PMD report.

## Best Practices

- **Run Locally First**: Always test your PMD configuration locally before adding it to the pipeline.
- **Keep Reports Organized**: Store PMD reports in a consistent location for easy access.
- **Regular Reviews**: Schedule regular reviews of PMD reports to address issues promptly.
- **Customize Rules**: Tailor PMD rules to fit your project's specific needs.

## Key Takeaways

- Adding a code quality stage ensures early detection of issues.
- Using Docker images simplifies environment setup.
- Artifacts are crucial for debugging and quality assurance.
- Regularly reviewing and updating PMD rules enhances code quality.

## Conclusion

Incorporating a code quality stage with PMD into your CI/CD pipeline is a proactive step towards maintaining a high-quality codebase. By following the steps outlined in this guide, you can catch potential issues early, making your development process more efficient and reliable.
