Welcome to this tutorial on how to publish HTML reports and dashboards using GitLab Pages. Whether you're looking to share your test results with a team or provide updates on project status via dashboards, this document will provide you with the necessary steps and best practices.

## Introduction

GitLab Pages allows users to publish static websites directly from a repository in GitLab. This feature can be particularly useful for displaying HTML reports generated during CI/CD pipelines, such as those from API testing. By the end of this guide, you will know how to move HTML reports into a `public` directory and configure GitLab CI to publish them as web pages.

## Prerequisites

Before you begin, ensure that the GitLab Pages feature is active on your GitLab instance. If you are not using gitlab.com, you may need to consult with your system administrator to enable this feature.

## Setting Up the Publishing Job in GitLab CI

To publish your HTML reports, you will need to add a new job to your `.gitlab-ci.yml` file. This job will handle the creation of a `public` directory and the movement of your HTML report into this directory.

### Step-by-Step Guide

1. **Create the `public` Directory**:

- Use the `mkdir` command to create a directory named `public` in the root of your project.

2. **Move the HTML Report**:

- Assuming you have an HTML report generated from previous API tests (e.g., `newman/report.html`), move this file to the `public` directory and rename it to `index.html`. This is necessary for GitLab Pages to recognize it as the default page to serve.

3. **Update the `.gitlab-ci.yml` Configuration**:

- Add a new stage called `publishing` at the end of your pipeline stages.
- Define a job named `pages` under this stage with the necessary scripts to create the directory and move the file, as shown below:

```yaml
stages:
  - build
  - test
  - deploy
  - post deploy
  - publishing

pages:
  stage: publishing
  script:
    - mkdir public
    - mv newman/report.html public/index.html
  artifacts:
    paths:
      - public
```

#### `script:`

This section lists the shell commands that will be executed when the job runs.

1. **`mkdir public`**

- Creates a new directory named `public`. This directory will be used to store the files that will be deployed to GitLab Pages.

2. **`mv newman/report.html public/index.html`**

- Moves (or renames) the file `report.html` from the `newman` directory to `public/index.html`. This effectively sets `index.html` as the main entry point for the GitLab Pages site.

#### `artifacts:`

This section specifies the files or directories that should be preserved and made available after the job completes.

- **`paths:`**
  - Lists the paths to be included as artifacts.

- **`- public`**
  - The `public` directory will be included as an artifact. In the context of GitLab Pages, this is the directory that GitLab will serve as the static website.

## Accessing GitLab Pages

After setting up the publishing job, GitLab CI will automatically push the content of the `public` folder to GitLab Pages after the pipeline completes. To view your newly published page:

1. **Navigate to Your Project Settings**:

- Go to `Settings` > `Pages` to find the URL where your page is being served.

2. **Initial Deployment Wait Time**:

- Note that the first deployment might take up to 30 minutes. Patience is key here!

3. **Accessing Your Page**:

- Once the page is live, you can click on the provided URL to view your HTML report as a web page.

## Best Practices

- **Verify Access**: Ensure your GitLab Pages site is accessible to your intended audience, adjusting project visibility settings as necessary.
- **Continuous Updates**: Regularly update your pipeline script to accommodate new reports or changes in your project structure.
- **Security**: Be mindful of sensitive information displayed in your reports, as GitLab Pages are publicly accessible by default.

## Key Takeaways

- GitLab Pages is an effective tool for publishing HTML reports from CI/CD pipelines.
- Proper setup in the `.gitlab-ci.yml` file is crucial for automating the publishing process.
- The visibility of your reports can enhance collaboration and transparency within teams.

## Conclusion

By following the steps outlined in this guide, you can leverage GitLab Pages to publish detailed HTML reports and dashboards, enhancing the visibility and accessibility of vital project metrics and outcomes. This capability is integral for maintaining transparency and collaboration in software development projects.
